## 19/10/26 PM — Paints forecast tables ZPPT_PNT_FCST_YR / _QT / _MN; GUI status steps

Arnav: the Paints annual, quarterly and monthly forecasts go into new tables because the
structure differs; and the status is not created, so give the manual steps.

**DDIC, new:** `ZDO_FCST_KL` (DEC 13,3), `ZDO_FCST_CR` (DEC 13,4); `ZDE_PACK_SIZE`,
`ZDE_QTY_CARTON`, `ZDE_FCST_KL`, `ZDE_FCST_CR`; tables `ZPPT_PNT_FCST_YR` (92 fields),
`ZPPT_PNT_FCST_QT` (68), `ZPPT_PNT_FCST_MN` (50) = the Adhesive tables field for field plus
NAME1, BRAND, PACK_SIZE, PACK_UNIT, QTY_CARTON, BRGEW (ref GEWEI), the per-month KL and CR
fields, and on annual and monthly WAERS + PRICE (ref WAERS) which the Adhesive tables lack.
Generated by `tools/mktables.py` from the Adhesive XMLs so the element order that imported
is kept; MSL moved before the audit fields on the monthly table.

**Code:** `ZCL_PP_FCST_PNT=>SAVE_PAINTS` (new, public): rows with MARK and a forecast number
→ CORRESPONDING into the Paints table, created-by preserved, MODIFY, own COMMIT; a refused
row gets light 1 and a message. `ZPP_FORECAST_PAINTS` `SAVE_SELECTED`: after the engine's
SAVE and the copy-back, MARK is cleared on every row, set again on the rows the engine saved
(light 3), and `SAVE_PAINTS` runs. **Two writes by design:** the shared tables are still
written by the engine because it reads the business forecast / additional / MSL / price back
from them, the change upload needs the shared row, the number is shared through them and
ZFCST_RPT reads them. Dropping the shared write means changing the engine — not done.

**Manual:** `MANUAL_STEPS.md` (+ docx) — SE41 status, two routes (copy from ZPP_FORECAST's
PF_STATUS, or from SALV_STANDARD with the four buttons added, function codes / icons
listed), SE93 for the two tcodes, SM30 config rows, optional SE54 / SE11.

ZIP rebuilt: 20 files. Static checks pass; not syntax-checked on a system. TR: none.
