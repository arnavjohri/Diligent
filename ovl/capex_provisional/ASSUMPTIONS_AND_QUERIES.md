# Provisional Capex / Opex (OVL) — Assumptions and Queries

Project OVL · requirement received as `SAP_Automation_Provisional_Capex_Process_-V3.xlsx`
(filed 18/11/2026, sent again 20/11/2026 — the same file) · prepared 20/11/2026

Requirement as received (sheet *Capex USD*, rows 5–9): *"1. Punching of Category wise breakup of
Cumulative Capex on each fortnight end by BU. 2. Check-if cumulative Capex is less than prior period
Cumulative Capex, show error. 3. BU can't decrease cumulative Capex, it has to show minimum capex of
prior reported amount. 4. SAP will show prior reported cumulative capex pre-filled as long as no
amount is punched in current period. 5. Separate Colour Coding for frozen amounts, that cannot be
changed by BU, amouts that are pre filled and for amounts that are punched in curret fortnight."*
Also: *"If errror in any marginal capex, it will show 0, however error values should not be accepted
by SAP"* (Capex USD B174) and *"Negative No.s can't be punched in the cells as input by BU"*
(Opex USD D3).

The ask is worded as "a report". What the sheet describes is an entry screen whose figures are
saved, checked against the previous fortnight and frozen, with the reports (the tabs) calculated
from those saved figures. Proposed delivery: custom tables, one entry transaction, one report
transaction. Nothing is read from postings and no standard object is changed.

Each item: the question, where it comes from, what will be built if no answer arrives, and what
changes if that assumption is wrong. **Items 1, 3, 5, 8, 10, 11, 13 and 15 decide table keys and
field types — they are needed before the tables are created.** The rest can be answered while the
build runs.

Taken as given from the sheet, not queried: mid-month column = increase in the first fortnight;
month column = increase over the full month; quarter = three months; year to date = four quarters;
balance = budget − year to date; utilisation = year to date ÷ budget. The Excel turns a failed
check into 0 in these columns; in SAP the entry is refused, so that case does not arise.

Deliberately **not planned** (not in the sheet): approval workflow, e-mail reminders at cutoff,
upload from Excel, a Fiori app, print forms, any read of actual postings, load of FY 2026-27 history.
